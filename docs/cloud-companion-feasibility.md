# 云端陪伴档案与 Agent 接入可行性核查

核查日期：2026-10-31。仅文档与现有代码核查，未购买资源、未完成平台入驻或真机联调，未修改线上功能。

## 已确认的产品决定

- 用户免费；开发者新增云服务预算目标每月人民币 100 元以内。
- 核心流程是发现变化、记录观察、行动与回访复盘，不只是重复测分。
- 多只狗使用稳定 ID，云端为统一档案来源，Web、小程序和 Agent 不各建独立档案。
- Web/小程序自由对话使用用户自己的模型 API；外部 Agent 使用宿主模型和用户自己的额度。
- 优先接入 WorkBuddy，以及普通豆包手机 App；不以豆包工作或调用豆包 API 冒充手机 App 接入。

## 可行性结论

### WorkBuddy：文档支持，尚未联调

官方连接器文档支持远程 HTTPS MCP、Skill、OAuth 2.1 + PKCE 与用户自填 Token。推荐远程 MCP + Skill，用户私有档案必须鉴权。平台支持不代表已通过市场审核，也不代表所有客户端版本功能相同。

初期工具：列出授权宠物、查询指定日期观察、检索带来源的知识、预览与确认保存记录、生成确定性复盘摘要。

写入不能仅依赖 Skill 中一句“先确认”：服务端生成短期写入意图，绑定用户、宠物、内容版本和过期时间，确认后幂等提交。修改、删除、导入单独授权；禁止用模型参数中的 ownerId 作为身份依据。

### 普通豆包手机 App：接入未证实，不能承诺首发

豆包开放平台可见内容介绍 Skill、插件和 MCP，但明确出现“豆包工作”，未找到足以证明普通手机 App 支持第三方私有档案授权与读写的官方说明。

这不等于确认“不支持”。在得到官方确认、开发者权限并完成手机实测前，将此渠道标记为待验证；可开发通用工具层，但不对用户宣传已接入豆包手机 App。无该能力时，其他渠道可独立测试，不替换用户指定的平台。

### 微信小程序：技术路线可行，现有 Web 不能原样搬过去

- 小程序需要新的界面适配、微信登录服务端校验、账户与宠物权限、云数据存储和备份恢复。
- 小程序请求有服务器域名配置限制；任意用户填写的模型地址不能照搬网页直连。
- 第一版可限制为已配置合法域名的服务商；仍需验证对应接口、请求参数与流式响应。
- 如需通用中转，用户模型密钥会经过本方服务器，必须另行明确同意、不落库、不写日志，增加目标地址白名单、SSRF/重定向防护、超时与流量限额。此路线尚未批准，不默认实施。
- 微信身份不是 Web 与 Agent 的自动统一登录。需建立自己的用户 ID 和一次性、可撤销的账号关联流程，不能按昵称或宠物名称自动合并。
- 不建议首版保存完整聊天、报告原件或不限量照片；模型仅获得用户授权的最小必要档案。

## 现有代码差距

- `lib/careMemory.ts` 仍使用浏览器 localStorage，以昵称和品种组成记录键。
- `app/api/account/route.ts` 返回 410；并非现成可用的云登录接口。
- `lib/server/store.ts` 是旧实验的本地 JSON 存储，生产环境默认禁止使用，不能作为多实例云端档案数据库。
- 现有 generateResult 与本地知识规则可复用；账号、云档案、跨端授权和恢复均需新开发。

## 月度预算：目标而非报价

CloudBase 官网检索到个人版限时价格 19.9 元/月，包含 40,000 资源点；付费套餐可超限按量使用。优惠期限、实际购买价及备份权益需购买前在控制台确认，不能将限时价格当永久成本。

内部预算分配建议：后端基础 20 元、独立备份 20 元、接口/流量/监控预留 20 元、余量 40 元，总计 100 元。该分配不是服务商报价，也尚未证明真实负载能落在其中。现有域名/Web 费用、小程序认证等一次性或年度费用另列，不悄悄挤进此预算。

用于压测的假设：100 个家庭、平均两只狗、每狗每天一条约 2KB 记录，原始记录一年约 146MB（十进制估算）。不含索引、版本历史、备份、日志、档案、网络和照片；不能据此推出套餐支持多少用户。若每天 100 个活跃用户、每人 12 次请求，约 36,000 次请求/月，也不能与资源点一比一换算。

上线前必须测量每次读写、查询、导出、备份和 MCP 会话的真实消耗，再核算月度费用。用短请求型 Streamable HTTP 避免无必要的常驻连接，具体部署适配仍需验证。

### 超额与可靠性

- 告警不等于硬限额，不能承诺账单绝不会超过 100 元。
- 设置 50/75/90 元内部告警目标，服务端控制请求频率、导出大小和照片容量；账单延迟仍有风险。
- 接近预算时先暂停新注册、照片上传和高成本统计，保留已有用户基本读取与导出；不能为省钱删除记录。
- 可靠性要求先采用日备份、至少保留七天、独立故障域、定期恢复演练的设计目标；并非已交付承诺。是否能在预算内实现是上线门槛。
- 删除、撤销授权与备份过期清理要有明确规则；用户本地导出是补充，不替代运营方备份。

## 进入开发前的验证门槛

1. 确认现有小程序主体、AppID、认证/备案状态、可申请类目；不在聊天提交 AppSecret。
2. 确认 WorkBuddy 开发者权限、目标客户端版本，完成一只测试宠物的授权读写及撤销测试。
3. 向豆包确认普通手机 App 是否开放 Skill/MCP、第三方授权与工具写入；无明确答复则保持待验证。
4. 用模拟密钥和模拟服务验证小程序 BYOK 路线，不调用用户真实模型、不消耗真实 Token。
5. 只用合成档案测跨用户/跨宠物权限、并发冲突、写入幂等和恶意输入。
6. 核对供应商实际定价、备份权益与限额机制，完成负载测试和一次完整恢复演练。
7. 小程序提交审核前核对类目、隐私政策、数据处理及模型服务要求；本报告不代替平台审核或合规意见。
